# 北京 PM2.5 探索性数据分析（EDA）

这是我学习 pandas / numpy 时做的第一个完整数据分析练习。项目对北京 2010—2014 年的逐小时 PM2.5 浓度和同期气象数据做清洗和探索性分析，主要看 PM2.5 在时间上的变化规律，以及它和温度、气压、风速、风向、降水等气象因素之间的关系，也为后面用机器学习预测 PM2.5 做一点准备。

## 一、数据来源

- 数据集：UCI Machine Learning Repository —— **Beijing PM2.5 Data Set**
- 数据集页面：<https://archive.ics.uci.edu/dataset/381/beijing+pm2-5+data+set>
- 直链下载：<https://archive.ics.uci.edu/ml/machine-learning-databases/00381/PRSA_data_2010.1.1-2014.12.31.csv>
- 数据为北京美国大使馆观测点 **2010-01-01 至 2014-12-31 的逐小时数据，共 43824 条**，缺失值在文件中记为 `NA`。
- 下载后放到 `data/` 目录，文件名保持 `PRSA_data_2010.1.1-2014.12.31.csv`（`data/` 已写进 `.gitignore`，数据文件不会上传到 GitHub）。

## 五、主要发现

1. **季节差异明显**：逐月均值在 2 月最高（约 125.7 微克/立方米）、8 月最低（约 80.0 微克/立方米），整体上秋冬季的污染程度高于春夏季（图 03）。
2. **一天之内有起伏**：夜间到凌晨浓度较高，午后到下午最低，白天后浓度明显下降（图 04）。
3. **和风的关系明显**：PM2.5 浓度与累积风速 Iws 呈负相关，风越大浓度越低；从风向看，静风/多变（cv）时平均浓度最高，西北风（NW）时最低（图 05、图 06）。
4. **重污染天的特征**：按日均 PM2.5 大于 150 微克/立方米划分，重污染天约占有效天数的 20%；这些天里静风/多变（cv）的占比从普通天的约 9% 升到约 25%，西北风（NW）则从约 43% 降到约 23%，重污染天往往伴随着静风、缺少西北风（图 07）。

## 六、机器学习阶段（W2-W5）

EDA 之后开始做预测，notebook 分两个：`W2_线性回归.ipynb` 是回归入门，`W3_特征工程与分类.ipynb` 是一周的完整流程（对应计划表 W3-W5）。

### 回归：预测下一小时的 PM2.5 浓度

用 2010-2013 训练、2014 测试，指标是 RMSE 和 R²。

| 模型 | 特征 | 划分 | RMSE | R² |
| --- | --- | --- | --- | --- |
| 均值基线（永远猜训练集均值） | — | 时序 | 93.5 | ≈0 |
| **持久性基线（直接用上一小时）** | — | 时序 | **22.14** | **0.9440** |
| 线性回归（裸特征） | 6 气象 | 随机 | 82.3 | 0.232 |
| 多项式 + Ridge（degree=3, alpha=0.01） | 6 气象 | 随机 | ≈77 | ≈0.325 |
| 线性回归 | 时序特征 | 时序 | 82.14 | 0.2287 |
| KNN（k=5） | 时序特征 | 时序 | 83.64 | 0.2002 |
| **KNN（k=98，网格搜索最优）** | 时序特征 | 时序 | **75.96** | **0.3404** |

### 分类：预测下一小时是否重污染（pm2.5 ≥ 150）

| 模型 | AUC | Precision | Recall | F1 |
| --- | --- | --- | --- | --- |
| KNN 分类（k=5，只用气象+周期特征） | 0.7153 | 0.4631 | 0.3670 | 0.4095 |
| 逻辑回归（只用气象+周期特征） | 0.7669 | 0.5167 | 0.1057 | 0.1755 |
| **逻辑回归（加 lag / rolling）** | **0.9893** | 0.8136 | 0.9625 | 0.8818 |
| 逻辑回归（加 lag / rolling，C 调参） | 0.9891 | — | — | — |

### 四个结论

1. **lag 特征决定一切。** 只用气象特征时 AUC 只有 0.72~0.77，加上 lag1 和 rolling 后跳到 0.99。同一个模型，特征里有没有"上一小时"这一步之差。
2. **不平衡数据下不能只看 accuracy。** 重污染只占 21.8%，永远猜「不重污染」就有 79.7% 的准确率——KNN 只拿 78.5%，比瞎猜还差。所以改用 Precision / Recall / F1 / AUC 评价。
3. **阈值要按业务定。** 逻辑回归在默认 0.5 阈值下 Recall 只有 0.11（漏掉 89% 的重污染），因为模型被多数类带偏了；用 `class_weight='balanced'` 或把阈值调低可以把 Recall 拉到 0.96，代价是 Precision 下降。对预警任务来说，漏报比误报严重，所以应该选高 Recall。
4. **随机切分会明显高估性能。** 回归任务里，线性回归从 0.2287 涨到 0.2618（+0.03），KNN 从 0.2002 涨到 0.4171（+0.22）。KNN 受害更严重，因为它的预测本质就是「取最近的邻居平均」，而随机切分下测试样本最近的训练邻居平均只隔 1.3 小时，等于把答案直接放在它面前。

## 七、不足与下一步

- EDA 部分只做了**描述性分析**，得到的结论都是相关关系而不是因果关系。
- 逐年对比用的是浓度总量、2010 年初还有一段缺失，年际趋势比较粗略。
- 回归任务里所有模型都没能超过持久性基线，下一步要换梯度提升（XGBoost / LightGBM）和残差建模，并尝试把气象预报数据当作未来特征。
- 当前特征是「上一小时的真实值」，属于提前一小时预警；要做 24 小时预警，标签和特征的时间对齐要重新设计。
